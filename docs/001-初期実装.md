# 初期実装（2026-10-14）

## 何をしたか
- ブラウザ完結の静的HTML+JSでPDFエディターを新規作成（ビルド不要）
- 表示は pdf.js、書き出しは pdf-lib。元ページを `embedPage` で新規PDFへ埋め込み、その上に編集オブジェクトを描画
- 機能: テキスト、画像、四角/円/線/矢印、ペン、蛍光ペン、ページ操作（並べ替え/回転/削除/複製/空白挿入/結合/分割）、Undo/Redo

## なぜこの構成か
- 利用者が自分だけのローカルツールのため、ビルド環境や外部サービスを持たない構成を選択
- ライブラリは `vendor/` に同梱し、オフラインでも動作

## 設計メモ
- オブジェクトは「回転適用後の表示座標(pt, 左上原点)」で保持。ページ回転時は `rotObjCW` で座標を追従させる（テキスト・画像は向きを保つ）
- 書き出しは新規ページサイズ=表示サイズとし、元ページを回転付きで `drawPage`。元PDFの `/Rotate` と CropBox も考慮
- テキストは折り返しなし（改行のみ）にして、画面とPDFの見た目を一致させる
- 日本語フォントは静的TTFの BIZ UDPGothic（Regular/Bold）。Noto Sans JP の可変フォントは pdf-lib/fontkit で正しく埋め込めなかったため不採用
- プロパティ変更時は既定値(`DEF`)も更新し、次に作るオブジェクトへ引き継ぐ

## 動作確認
Playwright(Chromium)で、テキスト追加・四角・矢印・ペン・ページ回転・書き出し、画像挿入・リサイズ・不透明度・削除とUndo・PDF結合・ページ並べ替え・選択ページ保存を確認済み。書き出したPDFは poppler で描画して目視確認。

## 既知の問題・TODO
- **フォントのサブセット化が効かない**: `subset:true` だと文字が `.notdef` になるため全体を埋め込み、テキスト使用時にPDFが約3MB増える（太字使用でさらに増加）
- 元PDFの注釈・リンク・フォームフィールドは書き出し時に失われる（ページ内容は保持）
- 元PDF内の既存テキストの直接編集は未対応（白い四角で覆ってテキストを重ねる運用）
- 復号済みで保存されるため、元のパスワード保護は引き継がれない（再暗号化は未対応）
- 複数オブジェクト同時選択、グループ化、オブジェクトの任意角度回転、フォント選択は未対応
- 蛍光ペンは矩形のみ（フリーハンドはペンの不透明度を下げて代用可能）
- サムネイルには編集内容が反映されない

## 追記: 暗号化PDF対応（2026-10-14）
- 開く時に `/Encrypt` を検出したら qpdf-wasm（`vendor/qpdf.js|wasm`、初回のみ遅延読み込み）で復号し、復号済みバイト列を pdf.js / pdf-lib の両方に渡す
- 先に空パスワードで試行 → 編集制限のみのPDFは入力不要で開く。開くパスワードが必要な場合のみダイアログを表示（誤入力は再入力可、キャンセル可）
- pdf-lib は復号できず、暗号化PDFをそのまま書き出すと内容が壊れるため、復号をpdf-lib読み込みの前段に置いた
- パスワード解除（総当たり等）は行わない。知っているパスワードでの復号のみ
- qpdf の `printErr` フックが効かない版のため、終了コード2をパスワード誤りとして扱う

## 追記: Tailscale経由のアクセス（2026-10-14）
- `0.0.0.0` で待ち受けるとLAN側の全インターフェースに公開されるため不採用。`serve.py` で `127.0.0.1` と `tailscale ip -4` のIPにのみバインド
- 認証は無く、tailnet に参加している端末なら誰でも使える。共有tailnetの場合は Tailscale ACL でアクセス元を制限すること
- HTTP(非HTTPS)でも動作確認済み。HTTPSが必要になった場合は `tailscale serve` を前段に置く案がある
- 既知: 同じポートで別プロセスが動いているとバインドに失敗するメッセージを出す（`ss -ltnp | grep 8765` で確認）
